Введение

Актуальность темы

В современном мире всё большее число людей занято умственным трудом, связанным с длительным нахождением за рабочим местом. По данным Всемирной организации здравоохранения (ВОЗ), офисные работники проводят в сидячем положении более восьми часов в сутки, что влечёт за собой целый ряд серьёзных последствий для здоровья. Так, у 65% офисных работников диагностируются заболевания опорно-двигательного аппарата, вызванные гиподинамией; 76% специалистов в сфере информационных технологий испытывают профессиональное выгорание. Исследования Гарвардской школы общественного здравоохранения (COGfx Study, 2015) установили, что повышение концентрации углекислого газа (CO₂) в помещении выше 1000 ppm снижает когнитивные способности сотрудников на 50%. Неправильное освещение рабочего места (менее 300 люкс) приводит к усталости глаз у 80% пользователей персональных компьютеров.

Существующие коммерческие решения — Xiaomi Mi Air Quality Monitor (~150 000 ₸) и Netatmo Weather Station (~200 000 ₸) — направлены исключительно на пассивный мониторинг и не предлагают инструментов управления продуктивностью. Бюджетные DIY-решения на базе Arduino Uno лишены беспроводной передачи данных и удобного интерфейса. Это определяет актуальность данной курсовой работы.

Цель работы

Разработать и реализовать интеллектуальную станцию мониторинга здоровья на рабочем месте NEXIS Wellness Station, объединяющую контроль параметров микроклимата, управление продуктивностью по технике Pomodoro, систему активных уведомлений и веб-дашборд с графиками в реальном времени.

Задачи проекта

  • Провести обзор и сравнительный анализ существующих решений и технологий в области IoT-мониторинга.
  • Обосновать выбор аппаратной платформы (ESP32) и датчиков.
  • Разработать принципиальную схему устройства и собрать аппаратный прототип.
  • Разработать прошивку ESP32 на C++, включающую модули датчиков, дисплея, Pomodoro, алертов и аппаратных прерываний (ISR).
  • Реализовать HTTP-интеграцию ESP32 с веб-сервером.
  • Разработать веб-дашборд на FastAPI + SQLite + Socket.IO с браузерным SPA-интерфейсом.
  • Провести всестороннее тестирование системы и разработать техническую документацию.

Объект и предмет исследования

Объект исследования — системы мониторинга параметров окружающей среды и устройства для повышения продуктивности на рабочем месте.

Предмет исследования — методы интеграции мониторинга микроклимата с инструментами тайм-менеджмента на базе микроконтроллера ESP32 с передачей данных на веб-сервер.

1.5 Техника Pomodoro как метод управления продуктивностью

Техника Pomodoro разработана Франческо Чирилло в конце 1980-х годов. Принцип: 25 минут сосредоточенной работы → 5 минут перерыва → после 4 циклов — длинный перерыв 15–30 минут.

Исследования когнитивной психологии (Baddeley, 2012; Kahneman, 2011) подтверждают, что принудительное чередование концентрации и отдыха повышает производительность на 35–40%, снижает уровень стресса и уменьшает вероятность выгорания.

В NEXIS Wellness Station Pomodoro реализован с обратным отсчётом на LCD, звуковым сигналом, счётчиком циклов, автоматической паузой при отсутствии движения (PIR) и логированием на веб-сервер.

1.6 Протоколы передачи данных во встроенных системах

I2C — двухпроводной интерфейс (SDA/SCL). На шине GPIO21/22: BME280 (0x76), BH1750 (0x23), LCD 1602 (0x27). Скорость — 100 кбит/с.

UART — асинхронный последовательный интерфейс. Serial2 (RX=GPIO16, TX=GPIO17, 9600 бод) для датчика ZM106-VOC.

Wi-Fi / HTTP — ESP32 отправляет JSON POST-запрос на эндпоинт /api/data каждые 10 секунд.

WebSocket (RFC 6455) — сервер мгновенно рассылает обновления всем браузерам через Socket.IO-событие sensor_update.

1.7 Стек технологий веб-дашборда

FastAPI (Python) — асинхронный веб-фреймворк (ASGI), автогенерация Swagger UI, валидация данных через Pydantic.

python-socketio — реализация WebSocket/Socket.IO для мгновенной передачи данных браузерам.

SQLite — встраиваемая СУБД, хранит показания датчиков, журнал Pomodoro и журнал алертов в файле nexis.db.

Chart.js — JavaScript-библиотека интерактивных графиков (спарклайны, исторические линии, тепловые карты).

2.4 Программная реализация прошивки ESP32

Прошивка написана на C++17 (Arduino Framework, PlatformIO). Состоит из двух файлов: config.h — константы (Wi-Fi, пины, пороги, интервалы) и main.cpp (~750 строк) — вся логика.

Алгоритм главного цикла loop():

Каждые 10 000 мс:
  readBME280()        → T, H, P по I2C
  readZM106()         → CO₂ по UART (каждые 5 с)
  readBH1750()        → освещённость по I2C
  readNoise()         → шум (20 замеров → пик)
  readPIR()           → движение (ISR-флаг + GPIO)
  checkThresholds()   → alertLevel (OK/WARN/DANGER)
  updateLED()         → RGB LED по alertLevel
  postSensorData()    → HTTP POST на FastAPI

Каждые 3 000 мс:
  updateDisplay()     → смена страницы LCD

Постоянно (без задержки):
  handleButtons()     → обработка ISR-флагов кнопок
  updatePomodoro()    → обратный отсчёт таймера
  checkWiFi()         → переподключение при разрыве

2.4.6 Механизм прерываний в ESP32

Прерывание (interrupt) — аппаратный сигнал, вынуждающий процессор приостановить текущий код и немедленно выполнить ISR (Interrupt Service Routine). В отличие от опроса (polling), прерывание гарантирует мгновенную реакцию независимо от загруженности основного цикла.

РежимКонстантаОписание
Спадающий фронтFALLINGСрабатывает при HIGH→LOW
Нарастающий фронтRISINGСрабатывает при LOW→HIGH
Любое изменениеCHANGEЛюбое изменение уровня

Таблица 2.5 — Режимы GPIO-прерываний ESP32

Ключевые требования к ISR: атрибут IRAM_ATTR (код в IRAM без задержки Flash-кэша), минимальное тело (только установка флага), переменные volatile.

Реализованные прерывания:

ИсточникПинРежимДействие
Кнопка MODEGPIO32FALLINGСмена экрана LCD
Кнопка OKGPIO33FALLINGЗапуск / стоп Pomodoro
PIR HC-SR501GPIO27RISINGМгновенная фиксация движения
 
// Volatile-флаги — атомарно пишутся в ISR, читаются в loop()
volatile bool isrBtnMode = false;
volatile bool isrBtnOK   = false;
volatile bool isrPIR     = false;

// ISR-обработчики в IRAM (только установка флага)
void IRAM_ATTR onBtnMode() { isrBtnMode = true; }
void IRAM_ATTR onBtnOK()   { isrBtnOK   = true; }
void IRAM_ATTR onPIR()     { isrPIR     = true; }

// Регистрация в setup():
attachInterrupt(digitalPinToInterrupt(PIN_BTN_MODE), onBtnMode, FALLING);
attachInterrupt(digitalPinToInterrupt(PIN_BTN_OK),   onBtnOK,   FALLING);
attachInterrupt(digitalPinToInterrupt(PIN_PIR),      onPIR,     RISING);

// Паттерн «флаг + обработка в loop()» — антидребезг 200 мс:
if (isrBtnMode && now - btnModeLast > DEBOUNCE_MS) {
    isrBtnMode = false;
    btnModeLast = now;
    state.displayPage = (state.displayPage + 1) % 5;
    updateDisplay();
    beepOK();
}

Преимущество перед polling: при polling нажатие кнопки во время HTTP-запроса (42 мс) могло быть пропущено. Прерывание фиксирует событие мгновенно в аппаратном стеке.

Заключение

В ходе выполнения курсовой работы поставленная цель достигнута в полном объёме: разработана и реализована интеллектуальная станция мониторинга здоровья на рабочем месте NEXIS Wellness Station, объединяющая мониторинг параметров микроклимата, Pomodoro-таймер, систему алертов и веб-дашборд с визуализацией данных в реальном времени.

Все семь задач выполнены:

  1. Проведён анализ рынка — преимущество NEXIS: функциональность в 1.5–2 раза выше при стоимости в 6–13 раз ниже коммерческих аналогов.
  2. Обоснован выбор ESP32 DevKit V1 как единственной доступной платформы, обеспечивающей одновременно 7 датчиков, Wi-Fi и достаточную производительность.
  3. Разработана схема и собран прототип с 7 датчиками по интерфейсам I2C, UART, 1-Wire, ADC, GPIO.
  4. Разработана прошивка (~750 строк C++): датчики, LCD, Pomodoro, алерты. Реализованы аппаратные прерывания ISR для кнопок (FALLING-edge) и PIR (RISING-edge) с volatile-флагами и debounce 200 мс.
  5. Реализована HTTP-интеграция: JSON POST каждые 10 с, авто-переподключение Wi-Fi.
  6. Разработан веб-дашборд: FastAPI + SQLite + Socket.IO (20+ API), 10-страничный SPA на 6 JS-модулях (~3000 строк): достижения, корреляционный анализ Pearson, тепловая карта 7×24, PDF-экспорт, Wellness Index.
  7. Проведено тестирование: 17/17 тест-кейсов пройдено. 7-суточный нагрузочный тест подтвердил отсутствие утечек памяти.

Новизна разработки: ни одно из рассмотренных решений не сочетает мониторинг 5+ параметров микроклимата с Pomodoro-таймером, аппаратными прерываниями ISR, многоуровневыми алертами и открытым веб-дашбордом в рамках устройства стоимостью до 20 000 ₸.

Перспективы: интеграция алгоритмов машинного обучения для предиктивного анализа качества воздуха; поддержка датчиков PM2.5 и TVOC; мобильное приложение; облачное хранение данных.

В.1 Инициализация setup() и главный цикл loop()

void setup() {
    Serial.begin(115200);
    // Регистрация аппаратных прерываний
    attachInterrupt(digitalPinToInterrupt(PIN_BTN_MODE), onBtnMode, FALLING);
    attachInterrupt(digitalPinToInterrupt(PIN_BTN_OK),   onBtnOK,   FALLING);
    attachInterrupt(digitalPinToInterrupt(PIN_PIR),      onPIR,     RISING);
    Wire.begin(I2C_SDA, I2C_SCL);
    bme.begin(I2C_BME280);
    lightMeter.begin(BH1750::CONTINUOUS_HIGH_RES_MODE);
    lcd.init(); lcd.backlight();
    wifiConnect();
}

void loop() {
    uint32_t now = millis();
    if (now - lastSensorRead >= SENSOR_INTERVAL_MS) {
        readBME280(); readBH1750(); readNoise();
        readPIR();    readDHT11(); readMQ135();
        state.alertLevel = checkThresholds();
        updateLED();
        postSensorData();
        lastSensorRead = now;
    }
    if (now - lastDisplayChange >= DISPLAY_INTERVAL_MS) {
        state.displayPage = (state.displayPage + 1) % 5;
        updateDisplay();
        lastDisplayChange = now;
    }
    handleButtons();   // обрабатывает ISR-флаги
    updatePomodoro();
}

В.2 Прерывания (ISR)

volatile bool isrBtnMode = false, isrBtnOK = false, isrPIR = false;
void IRAM_ATTR onBtnMode() { isrBtnMode = true; }
void IRAM_ATTR onBtnOK()   { isrBtnOK   = true; }
void IRAM_ATTR onPIR()     { isrPIR     = true; }

void handleButtons() {
    uint32_t now = millis();
    if (isrBtnMode && now - btnModeLast > DEBOUNCE_MS) {
        isrBtnMode = false; btnModeLast = now;
        state.displayPage = (state.displayPage + 1) % 5;
        updateDisplay(); beepOK();
    }
    if (isrBtnOK && now - btnOKLast > DEBOUNCE_MS) {
        isrBtnOK = false; btnOKLast = now;
        if (state.pomoMode == SystemState::POMO_IDLE) pomoStart();
        else pomoStop();
    }
}

В.3 Функция проверки порогов алертов

AlertLevel checkThresholds() {
    AlertLevel level = ALERT_OK;
    if (sensors.zm106OK && sensors.co2 > THRESH_CO2_DANGER)
        level = ALERT_DANGER;
    else if (sensors.zm106OK && sensors.co2 > THRESH_CO2_WARN)
        level = max(level, ALERT_WARN);
    if (!isnan(sensors.temperature)) {
        if (sensors.temperature > THRESH_TEMP_DANGER) level = ALERT_DANGER;
        else if (sensors.temperature > THRESH_TEMP_WARN) level = max(level, ALERT_WARN);
    }
    if (!isnan(sensors.light) && sensors.light < THRESH_LIGHT_WARN)
        level = max(level, ALERT_WARN);
    if (!isnan(sensors.noise) && sensors.noise > THRESH_NOISE_DANGER)
        level = max(level, ALERT_WARN);
    return level;
}

## Возможные вопросы комиссии и ответы

**Q: Почему ESP32, а не Arduino Uno?**  
A: ESP32 имеет встроенный Wi-Fi/Bluetooth, двухъядерный процессор 240 МГц, 520 КБ RAM и поддерживает аппаратные прерывания на всех GPIO. Arduino Uno не поддерживает Wi-Fi без внешнего модуля и имеет всего 2 КБ RAM.

**Q: Зачем прерывания? Polling не справился бы?**  
A: PIR-датчик фиксирует движение длительностью 0.3–0.5 с. При 10-секундном интервале опроса и загруженном loop() (HTTP POST занимает ~42 мс) система могла пропустить событие. Прерывание фиксирует флаг мгновенно в аппаратном стеке, независимо от состояния loop().

**Q: Почему не использовали RTOS?**  
A: Для данной задачи Arduino Framework с кооперативной многозадачностью (millis-таймеры) достаточен. RTOS добавил бы сложность без реального выигрыша при одном потоке данных.

**Q: Точность датчика ZM106 vs NDIR-датчиков?**  
A: ZM106 — electrochemical VOC датчик, не истинный CO₂-сенсор типа NDIR (SCD41). Он измеряет суммарные VOC и коррелирует с CO₂. Для учебного проекта погрешность ±15% приемлема. В перспективах указана замена на SCD41.

**Q: Как защищён API от посторонних запросов?**  
A: В текущей версии API работает в локальной сети без аутентификации — это сознательное упрощение для прототипа. В продуктивной версии потребуется API-ключ или JWT.

**Q: Какова точность BME280?**  
A: BME280 (Bosch) — промышленный датчик: температура ±1°C, влажность ±3%, давление ±1 hPa. Это превышает требования ГОСТ 30494-2011 для мониторинга микроклимата.

**Q: Почему SQLite, а не PostgreSQL/Redis?**  
A: SQLite не требует отдельного сервера, работает на любой ОС без установки. Для скорости записи 1 запись/10 сек (8640 записей/сутки) SQLite избыточно производителен. При масштабировании до сотен устройств потребовался бы переход на PostgreSQL + TimescaleDB.

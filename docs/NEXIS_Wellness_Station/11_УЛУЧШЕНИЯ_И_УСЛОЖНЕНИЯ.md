### ⭐ ВАРИАНТ 1: Интеллектуальная система мониторинга с адаптивными порогами (РЕКОМЕНДУЕТСЯ)

#### 📝 Описание
Вместо фиксированных порогов для уведомлений, система **обучается** на основе истории данных и **автоматически адаптирует пороги** под конкретные условия пользователя.

#### 🔧 Технические детали

**1.1. Сбор статистики и обучение**
- Система собирает данные за **первые 7 дней работы**
- Вычисляет **среднее**, **медиану**, **стандартное отклонение** для каждого параметра
- Определяет "нормальные" условия для конкретного помещения
- Строит **динамические пороги**: `порог = среднее + 2×σ` (где σ — стандартное отклонение)

**1.2. Умные уведомления**
- Не просто "CO2 высокий", а:
  - "CO2 выше нормы на 30% — откройте окно"
  - "Освещённость низкая для этого времени суток — включите свет"
  - "Температура растёт быстрее обычного — проверьте вентиляцию"
- **Анализ трендов:** "За последние 3 часа качество воздуха ухудшается"
- **Предиктивные уведомления:** "Через 15 минут начнётся духота по статистике"

**1.3. Дневной/недельный анализ**
- Построение **графиков параметров** за день/неделю (отправка в Telegram как изображение)
- **Корреляционный анализ:** "Когда температура выше 24°C, ваша продуктивность падает на 20%"
- **Рекомендации:** "Оптимальное время для продуктивной работы: 10:00-12:00 и 15:00-17:00"

#### 💻 Программная сложность
- **Алгоритмы машинного обучения** (простые — скользящее среднее, экспоненциальное сглаживание)
- **Хранение истории** в SPIFFS/SD-карте (circular buffer на 7-30 дней)
- **Математические расчёты**: среднее, σ, тренды, корреляции
- **Графика**: построение графиков (например, библиотека Arduino_GFX или отправка данных в сервис типа ThingSpeak)

#### 💰 Дополнительная стоимость
- **SD-карта модуль** (для хранения данных): ~800₸
- Итого: **~800₸** + программная сложность

### ⭐ ВАРИАНТ 2: Многорежимная работа с автоматическим переключением

#### 📝 Описание
Система имеет **несколько режимов работы**, которые автоматически активируются в зависимости от ситуации.

#### 🔧 Режимы работы

**2.1. Режим "Работа" (Work Mode)**
- Активен, когда обнаружено присутствие человека
- Активный мониторинг всех датчиков (каждые 5 сек)
- Pomodoro таймер активен
- Все уведомления включены
- Дисплей яркий

**2.2. Режим "Отдых" (Break Mode)**
- Активируется после завершения Pomodoro цикла
- Релаксационные подсказки: "Пора размяться", "Сделайте 5 приседаний"
- Подсчёт шагов (если добавить акселерометр)
- Напоминание выпить воды

**2.3. Режим "Отсутствие" (Away Mode)**
- Активируется, если PIR не обнаруживает движение >15 минут
- Низкое энергопотребление
- Редкий опрос датчиков (каждые 60 сек)
- Дисплей выключен
- Только критические уведомления

**2.4. Режим "Ночь" (Night Mode)**
- Активируется по времени (22:00-07:00) или низкой освещённости
- Отключение звуковых уведомлений
- Очень тихая работа
- Только критические сообщения (пожар, высокий CO2)

**2.5. Режим "Фокус" (Focus Mode)**
- Запускается вручную через кнопку или Telegram
- Отключение всех уведомлений, кроме Pomodoro
- Максимальная концентрация
- Расширенная статистика продуктивности

#### 💻 Программная сложность
- **Конечный автомат** (State Machine) для управления режимами
- **Логика переключения** режимов
- **Разные параметры** для каждого режима
- **Переходы** между режимами с анимациями на дисплее

#### 💰 Дополнительная стоимость
- Опционально: **Акселерометр MPU6050** для подсчёта шагов: ~600₸
- Итого: **0-600₸** + программная сложность

### ⭐⭐⭐ ВАРИАНТ 7: СИСТЕМА ПРЕРЫВАНИЙ (INTERRUPTS) — ПОВЫШЕНИЕ ОЦЕНКИ

#### 📝 Описание
Использование **аппаратных прерываний** для мгновенного реагирования на события вместо постоянного опроса (polling). **Преподаватель рекомендует для повышения оценки!**

#### ❓ Что такое прерывания?

**Без прерываний (Polling):**
```cpp
// Постоянная проверка в цикле — неэффективно
void loop() {
  if (digitalRead(BUTTON_PIN) == LOW) {  // Проверяем каждый цикл
    handleButton();                       // Может пропустить нажатие
  }
  // ... другой код ...
  delay(100);  // Задержка → можем пропустить событие
}
```
**Проблемы:**
- ❌ Процессор тратит время на постоянную проверку
- ❌ Можем пропустить короткие события (быстрое нажатие кнопки)
- ❌ Задержки в коде → медленная реакция

**С прерываниями (Interrupt-driven):**
```cpp
// Прерывание — мгновенная реакция
void IRAM_ATTR buttonISR() {  // ISR = Interrupt Service Routine
  handleButton();              // Вызывается МГНОВЕННО при нажатии
}

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), buttonISR, FALLING);
}

void loop() {
  // Процессор занимается другими задачами
  // При нажатии кнопки — код МОМЕНТАЛЬНО прерывается
  // и выполняется buttonISR()
}
```
**Преимущества:**
- ✅ Процессор не тратит время на проверку
- ✅ Мгновенная реакция (микросекунды)
- ✅ Не пропускает события
- ✅ Более эффективное использование ресурсов

#### 🎯 ГДЕ В НАШЕМ ПРОЕКТЕ РЕАЛЬНО НУЖНЫ ПРЕРЫВАНИЯ

**❌ НЕ НУЖНЫ прерывания для:**
- DHT22, BH1750, MQ-135 — они опрашиваются раз в 5-10 секунд
- OLED дисплей — только вывод данных
- Winsen ZM106 (UART) — обрабатывается в основном цикле
- Telegram Bot — асинхронная обработка

**✅ РЕАЛЬНО НУЖНЫ прерывания для:**

#### 7.1. Кнопки управления (КРИТИЧНО)

**Проблема без прерываний:**
```cpp
// Пользователь нажимает кнопку паузы Pomodoro
// Но ESP32 в это время обрабатывает UART от VOC датчика (2-3 секунды)
// Результат: кнопка не сработала → плохой UX
```

**Решение с прерываниями:**
```cpp
volatile bool pauseButtonPressed = false;

void IRAM_ATTR pauseButtonISR() {
  pauseButtonPressed = true;  // Флаг устанавливается МГНОВЕННО
}

void setup() {
  attachInterrupt(digitalPinToInterrupt(PAUSE_BTN), pauseButtonISR, FALLING);
}

void loop() {
  if (pauseButtonPressed) {
    pauseButtonPressed = false;
    pausePomodoro();  // Обрабатываем в основном цикле
  }
}
```

**Что добавить:**
- 3 кнопки: Start/Pause, Stop, Mode
- Прерывания на FALLING edge
- Debouncing (защита от дребезга)

**Дополнительная стоимость:** 0₸ (кнопки уже есть)

#### 7.2. PIR датчик движения (ВАЖНО)

**Проблема без прерываний:**
```cpp
// Пользователь ушёл из комнаты
// Датчик сработал, но ESP32 спит в Deep Sleep
// Результат: система не переключилась в режим "Отсутствие" вовремя
```

**Решение с прерываниями:**
```cpp
void IRAM_ATTR motionDetectedISR() {
  // Прерывание выводит ESP32 из Deep Sleep
  // Переключение в режим "Работа" МГНОВЕННО
}

void setup() {
  attachInterrupt(digitalPinToInterrupt(PIR_PIN), motionDetectedISR, RISING);
  esp_sleep_enable_ext0_wakeup(PIR_PIN, 1);  // Пробуждение от Deep Sleep
}
```

**Преимущества:**
- ✅ Мгновенное переключение режимов
- ✅ Экономия энергии (Deep Sleep + пробуждение по прерыванию)
- ✅ Детектор активности работает всегда

**Дополнительная стоимость:** 0₸ (PIR уже есть)

#### 7.3. Энкодер для управления (ОПЦИОНАЛЬНО, УСЛОЖНЕНИЕ)

**Если добавить:**
- Rotary Encoder (энкодер вращения) вместо/вместе с кнопками
- Цена: ~400₸

**Зачем нужны прерывания для энкодера:**
```cpp
// Энкодер генерирует импульсы при вращении
// БЕЗ прерываний — пропускаем импульсы → неточный подсчёт
// С прерываниями — каждый импульс учитывается → точная позиция
```

**Пример:**
```cpp
volatile int encoderPosition = 0;

void IRAM_ATTR encoderISR() {
  if (digitalRead(ENCODER_B) == HIGH) {
    encoderPosition++;  // Вращение по часовой
  } else {
    encoderPosition--;  // Против часовой
  }
}

void setup() {
  attachInterrupt(digitalPinToInterrupt(ENCODER_A), encoderISR, CHANGE);
}

// Использование: регулировка порогов, навигация по меню
```

**Преимущества:**
- ✅ Точное считывание поворотов
- ✅ Удобное управление (как на профессиональных приборах)
- ✅ Усложнение проекта → больше баллов

#### 7.4. Аппаратные таймеры для Pomodoro (ПРОФЕССИОНАЛЬНЫЙ УРОВЕНЬ)

**Текущая реализация:**
```cpp
// В loop() проверяем время каждый цикл
unsigned long currentTime = millis();
if (currentTime - startTime >= POMODORO_TIME) {
  pomodoroComplete();
}
// Проблема: точность зависит от загруженности loop()
```

**С аппаратным таймером:**
```cpp
hw_timer_t * timer = NULL;

void IRAM_ATTR onPomodoroTimer() {
  // Прерывание вызывается ТОЧНО через 25 минут
  pomodoroComplete();
}

void setup() {
  timer = timerBegin(0, 80, true);  // Таймер 0, делитель 80, счёт вверх
  timerAttachInterrupt(timer, &onPomodoroTimer, true);
  timerAlarmWrite(timer, 25 * 60 * 1000000, true);  // 25 минут в микросекундах
  timerAlarmEnable(timer);
}
```

**Преимущества:**
- ✅ Аппаратная точность (не зависит от загрузки CPU)
- ✅ Освобождается основной цикл
- ✅ Профессиональный подход
- ✅ Можно реализовать несколько независимых таймеров

**Дополнительная стоимость:** 0₸ (встроено в ESP32)

#### 7.5. Watchdog Timer (ЗАЩИТА ОТ ЗАВИСАНИЯ)

**Проблема:**
```cpp
// Если программа зависла (бесконечный цикл, ошибка) → устройство не работает
// Нужна ручная перезагрузка → плохо для курсовой
```

**Решение:**
```cpp
#include "esp_task_wdt.h"

void setup() {
  // Watchdog таймер на 30 секунд
  esp_task_wdt_init(30, true);  // 30 сек, автоперезагрузка
  esp_task_wdt_add(NULL);       // Добавляем текущую задачу
}

void loop() {
  // Регулярно "кормим" watchdog
  esp_task_wdt_reset();
  
  // Если loop() зависнет → watchdog не получит reset
  // Через 30 сек → автоматическая перезагрузка
}
```

**Преимущества:**
- ✅ Защита от зависания
- ✅ Автоматическое восстановление
- ✅ Повышенная надёжность
- ✅ Усложнение проекта

**Дополнительная стоимость:** 0₸ (встроено в ESP32)


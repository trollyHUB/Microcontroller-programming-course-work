# 📱 ВЫБОР МИКРОКОНТРОЛЛЕРА

## ⚠️ Вариант 1: Arduino UNO (НЕ РЕКОМЕНДУЕТСЯ)

### ❌ ПОЧЕМУ ARDUINO UNO НЕ ПОДХОДИТ

| Параметр | Arduino UNO | ESP32 | Вердикт |
|----------|-------------|-------|---------|
| **Частота CPU** | 16 МГц | 240 МГц | ❌ Недостаточно для сложных вычислений |
| **RAM** | 2 KB | 520 KB | ❌ Критически мало! |
| **Flash** | 32 KB | 4 MB | ❌ Недостаточно для всех библиотек |
| **Wi-Fi** | ❌ Нет | ✅ Встроенный | ❌ Нужен внешний модуль (+3000₸) |
| **Bluetooth** | ❌ Нет | ✅ Встроенный | ❌ Нет возможности BLE |
| **Поддержка UART** | 1 порт | 3 порта | ❌ Недостаточно |
| **FreeRTOS** | ❌ Нет | ✅ Да | ❌ Нет многозадачности |
| **OTA обновления** | ❌ Нет | ✅ Да | ❌ Только через USB |
| **Поддержка SPIFFS/SD** | Ограничена | ✅ Полная | ❌ Проблемы с файловой системой |
| **Цена** | ~1,500₸ | ~3,000₸ | ❌ Экономия не оправдана |

### ⚠️ ТЕХНИЧЕСКИЕ ПРОБЛЕМЫ С ARDUINO UNO

#### 1. Критическая нехватка памяти
```cpp
// Пример реальных проблем:
- DHT22 библиотека: ~500 байт RAM
- BH1750 библиотека: ~300 байт RAM
- OLED дисплей: ~1024 байт буфер экрана
- Telegram Bot: НЕВОЗМОЖНО (требует 50-100 KB RAM)
- WiFi модуль: НЕВОЗМОЖНО
- Остаток для кода: ~200 байт ❌
```

#### 2. Невозможность реализации функций
- ❌ **Telegram Bot** — требует WiFi модуль и много RAM
- ❌ **Web-интерфейс** — нет WiFi, мало памяти
- ❌ **REST API** — невозможно
- ❌ **Адаптивные пороги** — недостаточно памяти для массивов данных
- ❌ **OTA обновления** — невозможно
- ❌ **Многозадачность** — нет FreeRTOS
- ❌ **Графики в реальном времени** — мало RAM

#### 3. Что можно реализовать на Arduino UNO (урезанная версия)
```
✅ Чтение 3-4 датчиков (DHT22, BH1750, MQ-135)
✅ Вывод на OLED дисплей
✅ Звуковые сигналы
✅ Сохранение на SD-карту (с ограничениями)
❌ Telegram
❌ WiFi
❌ Интеллектуальные функции
❌ Веб-интерфейс
```

### 🚫 ВЫВОД: ARDUINO UNO НЕ ПОДХОДИТ ДЛЯ ЭТОГО ПРОЕКТА

**Причины:**
1. Проект потеряет 80% функционала
2. Невозможна интеграция с Telegram (ключевое требование)
3. Нет интеллектуальных функций → оценка снизится
4. Проект станет примитивным → не пройдёт требования преподавателя

## ✅ Вариант 2: ESP32 (РЕКОМЕНДУЕТСЯ — ТЕКУЩИЙ ВЫБОР)

### Преимущества
- ✅ Встроенный WiFi/Bluetooth
- ✅ Достаточно RAM (520 KB)
- ✅ Высокая производительность (240 МГц, двухъядерный)
- ✅ FreeRTOS для многозадачности
- ✅ OTA обновления
- ✅ Поддержка всех необходимых библиотек
- ✅ Широкое сообщество разработчиков

### Недостатки
- ⚠️ Немного дороже (~3,000₸ vs 1,500₸)
- ⚠️ Чуть сложнее в программировании (но это плюс для курсовой!)

### 💰 Стоимость: 3,000₸

---

## ⭐ Вариант 3: ESP8266 (КОМПРОМИССНЫЙ)

### Характеристики
- **CPU:** 80/160 МГц
- **RAM:** 80 KB (критически мало!)
- **Flash:** 4 MB
- **WiFi:** ✅ Да
- **Bluetooth:** ❌ Нет
- **UART портов:** 1.5 (один полный, один TX только)
- **FreeRTOS:** Ограниченная поддержка

### Сравнение с ESP32

| Параметр | ESP8266 | ESP32 |
|----------|---------|-------|
| RAM | 80 KB | 520 KB |
| CPU ядра | 1 | 2 |
| Bluetooth | ❌ | ✅ |
| UART | 1.5 | 3 |
| ADC | 1 канал 10-бит | 18 каналов 12-бит |
| Цена | ~1,500₸ | ~3,000₸ |

### ⚠️ Проблемы ESP8266 для нашего проекта
- ❌ **80 KB RAM** — недостаточно для Telegram Bot + веб-сервера
- ❌ **Нет Bluetooth** — нет возможности BLE функций
- ❌ **Только 1 UART** — проблема с Winsen ZM106-VOC
- ❌ **1 ADC канал** — нельзя подключить MQ-135 + KY-037 одновременно
- ⚠️ Можно реализовать 60-70% функционала

### 💰 Стоимость: ~1,500₸

### 🤔 Когда выбрать ESP8266?
- Если критически важен бюджет
- Если не нужен Bluetooth
- Если готовы пожертвовать частью функционала

## 1. Датчик качества воздуха (VOC/CO2)

### 🎯 Текущий выбор: Winsen ZM106-VOC (3,500₸)

**Характеристики:**
- Измеряет: VOC (летучие органические соединения)
- Диапазон: 0-500 ppm
- Интерфейс: UART
- Точность: ±5%
- Калибровка: Автоматическая
- Время прогрева: 3 минуты

**Преимущества:**
- ✅ Профессиональный уровень
- ✅ Высокая точность
- ✅ UART интерфейс (усложняет проект)
- ✅ Подходит для курсовой работы

**Характеристики:**
- Измеряет: VOC + eCO2 (эквивалент CO2)
- Интерфейс: I2C
- Точность: Очень высокая
- Время отклика: 1 секунда
- Калибровка: Автоматическая с базовой линией

**Преимущества:**
- ✅ **Топовый сенсор** от швейцарской компании Sensirion
- ✅ Измеряет одновременно VOC и eCO2
- ✅ I2C — проще программировать, чем UART
- ✅ Отличная документация и библиотеки
- ✅ Используется в профессиональных устройствах
- ✅ Долгий срок службы (>15 лет)

**Недостатки:**
- ❌ Дороже на 1,500-2,500₸

**Где купить:**

**💰 Стоимость:** 5,000-6,000₸

- Точность: ±(30 ppm + 3%)

**Недостатки:**
- ❌ **Очень дорого** (почти весь бюджет проекта)

**Где купить:**
- AliExpress: "SCD30 sensor"

**💰 Стоимость:** 12,000-15,000₸

**🎓 Для курсовой:** ⭐⭐⭐⭐⭐ **ТОП выбор**, если бюджет позволяет

- ✅ Меньше энергопотребление

**Недостатки:**
- ⚠️ Точность влажности чуть ниже (±3% vs ±2%)

**💰 Стоимость:** 1,500₸

# ⚡ СИСТЕМА ПРЕРЫВАНИЙ — ДОПОЛНИТЕЛЬНЫЕ БАЛЛЫ

## 🎓 Рекомендация преподавателя

**Преподаватель указал:** Если добавить **аппаратные прерывания** (interrupt-driven architecture), можно получить **дополнительные баллы**.

### ❓ Что это значит?

**Прерывания (Interrupts)** — это механизм, при котором микроконтроллер **мгновенно прерывает** текущую задачу при возникновении важного события (нажатие кнопки, сигнал датчика, срабатывание таймера).

### 📊 Сравнение подходов

| Параметр | Без прерываний (Polling) | С прерываниями (Interrupt-driven) |
|----------|--------------------------|----------------------------------|
| **Реакция** | Медленная (10-100 мс) | Мгновенная (< 1 мс) |
| **Загрузка CPU** | Высокая (постоянная проверка) | Низкая (работа по событиям) |
| **Точность** | Низкая (можно пропустить событие) | Высокая (не пропускает) |
| **Энергопотребление** | Высокое | Низкое (Deep Sleep возможен) |
| **Сложность кода** | Простая (🔥🔥) | Высокая (🔥🔥🔥🔥) |
| **Оценка** | Средняя | Высокая ⭐ |

## 📚 ЧТО НУЖНО ИЗУЧИТЬ

### Минимум (для базовых прерываний):
1. `attachInterrupt()` / `detachInterrupt()`
2. `IRAM_ATTR` — размещение ISR в RAM
3. `volatile` — переменные для ISR
4. Типы триггеров: RISING, FALLING, CHANGE

### Продвинутый уровень:
5. Hardware timers — `timerBegin()`, `timerAttachInterrupt()`
6. Watchdog timer — `esp_task_wdt_*`
7. Critical sections — `portENTER_CRITICAL()` / `portEXIT_CRITICAL()`
8. Deep Sleep + External Wakeup
9. Debouncing (устранение дребезга)

### Экспертный уровень:
10. ISR оптимизация (минимальный код в ISR)
11. Race conditions и их избежание
12. FreeRTOS + interrupts интеграция

## ⚠️ ВАЖНО: "НЕ ПРЕРЫВАНИЯ РАДИ ПРЕРЫВАНИЙ"

### ❌ НЕПРАВИЛЬНО (бессмысленные прерывания):

```cpp
// ❌ Прерывание для медленного датчика
void IRAM_ATTR dht22ISR() {
  readDHT22();  // DHT22 читается раз в 5 сек — не нужны прерывания
}

// ❌ Прерывание для вывода на дисплей
void IRAM_ATTR displayISR() {
  updateDisplay();  // Обновление дисплея не критично по времени
}
```

**Почему плохо:** Прерывания добавлены только для галочки, без реальной пользы

### ✅ ПРАВИЛЬНО (осмысленные прерывания):

```cpp
// ✅ Критично по времени — кнопка "стоп звука"
void IRAM_ATTR muteButtonISR() {
  noTone(BUZZER_PIN);  // Пользователь хочет тишины СЕЙЧАС
}

// ✅ Нельзя пропустить — короткий импульс
void IRAM_ATTR pulseCountISR() {
  pulseCount++;  // Каждый импульс важен
}

// ✅ Аппаратная точность — таймер
void IRAM_ATTR timerISR() {
  pomodoroComplete();  // Ровно через 25:00, не 25:03
```

## 🏗️ Архитектура: Как это работает вместе

### Разделение задач (FreeRTOS):

```cpp
// Задача 1: Telegram Bot (в фоне, низкий приоритет)
void telegramTask(void *parameter) {
  while (true) {
    bot.getUpdates();  // Проверяем новые сообщения
    delay(1000);       // Раз в секунду
  }
}

// Задача 2: Веб-сервер (в фоне, низкий приоритет)
void webServerTask(void *parameter) {
  server.begin();
  while (true) {
    server.handleClient();  // Обрабатываем HTTP запросы
    delay(10);
  }
}

// Задача 3: Датчики (в фоне, средний приоритет)
void sensorsTask(void *parameter) {
  while (true) {
    readAllSensors();
    delay(5000);  // Каждые 5 секунд
  }
}

// ISR: ПРЕРЫВАНИЯ (мгновенная реакция, ВЫСОКИЙ приоритет)
void IRAM_ATTR buttonISR() {
  // Выполняется МГНОВЕННО при нажатии кнопки
  // НЕ ЖДЁТ завершения других задач
  buttonPressed = true;
}

void setup() {
  // Создаём задачи FreeRTOS
  xTaskCreate(telegramTask, "Telegram", 10000, NULL, 1, NULL);
  xTaskCreate(webServerTask, "WebServer", 10000, NULL, 1, NULL);
  xTaskCreate(sensorsTask, "Sensors", 10000, NULL, 2, NULL);
  
  // Подключаем прерывания
  attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), buttonISR, FALLING);
}
```

```cpp
// Глобальные флаги для взаимодействия ISR и задач
volatile bool pauseButtonPressed = false;
volatile bool emergencyStop = false;

// ISR — выполняется МГНОВЕННО
void IRAM_ATTR pauseButtonISR() {
  pauseButtonPressed = true;  // Просто устанавливаем флаг
}

void IRAM_ATTR emergencyStopISR() {
  emergencyStop = true;
  noTone(BUZZER_PIN);  // Немедленно выключаем звук
}

// Основной цикл — обрабатывает флаги
void loop() {
  // Проверяем флаги из ISR
  if (pauseButtonPressed) {
    pauseButtonPressed = false;
    pausePomodoro();
    
    // Уведомляем через Telegram (не блокируем)
    bot.sendMessage(chatId, "⏸️ Pomodoro приостановлен");
    
    // Обновляем веб-интерфейс
    updateWebStatus("paused");
  }
  
  if (emergencyStop) {
    emergencyStop = false;
    stopAllAlerts();
    bot.sendMessage(chatId, "🛑 Экстренная остановка");
  }
  
  // Остальная логика продолжается
  delay(10);
}

// Telegram задача работает независимо
void telegramTask(void *parameter) {
  while (true) {
    bot.getUpdates();  // Проверяем команды пользователя
    delay(1000);
  }
}
```

### Программная часть (сложность 🔥🔥🔥🔥🔥)

```cpp
// 1. Чтение гироскопа (100 раз в секунду!)
void readGyroscope() {
  mpu.getMotion6(&ax, &ay, &az, &gx, &gy, &gz);
}

// 2. PID регулятор (самая сложная часть)
void calculatePID() {
  // Вычисление ошибки по 3 осям
  errorRoll = targetRoll - currentRoll;
  errorPitch = targetPitch - currentPitch;
  errorYaw = targetYaw - currentYaw;
  
  // PID формула
  pidRoll = Kp * errorRoll + Ki * integralRoll + Kd * derivativeRoll;
  // ... аналогично для Pitch и Yaw
}

// 3. Микширование моторов (Motor Mixing)
void updateMotors() {
  motor1 = throttle + pidRoll + pidPitch + pidYaw;
  motor2 = throttle - pidRoll + pidPitch - pidYaw;
  motor3 = throttle + pidRoll - pidPitch - pidYaw;
  motor4 = throttle - pidRoll - pidPitch + pidYaw;
  
  // Ограничение 1000-2000 мкс (PWM)
  motor1 = constrain(motor1, 1000, 2000);
  // ... для всех моторов
}

// 4. Основной цикл — 100 Гц (каждые 10 мс)
void loop() {
  readGyroscope();      // Положение в пространстве
  readBluetooth();      // Команды с телефона
  calculatePID();       // Стабилизация
  updateMotors();       // Управление моторами
  delay(10);            // Точно 100 Гц
}
```

### Что программировать:

1. **PID регулятор** — сложнейшая математика (Kp, Ki, Kd коэффициенты)
2. **Калибровка гироскопа** — компенсация дрифта
3. **Motor mixing** — вычисление оборотов каждого мотора
4. **Failsafe** — что делать при потере сигнала
5. **Throttle curve** — нелинейное управление газом
6. **Complementary filter** — фильтрация шума гироскопа

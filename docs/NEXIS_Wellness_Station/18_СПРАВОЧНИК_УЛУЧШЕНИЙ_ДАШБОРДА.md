## 1. ТЕКУЩЕЕ СОСТОЯНИЕ

### Что у нас есть

| Файл | Строк | Статус | Комментарий |
|------|-------|--------|-------------|
| `main.py` | 348 | Хорошо структурирован | FastAPI + socketio, все endpoints работают |
| `app.js` | 1332 | Монолит — нужен рефакторинг | Всё в одном файле: конфиг, состояние, все страницы |
| `index.html` | 708 | Монолит | Вся HTML-разметка всех 6 страниц в одном файле |
| `style.css` | 740 | Монолит | Все стили в одном файле без разделения |

### Честная оценка уровня проекта

Это уже **выше среднего коммерческого пет-проекта**, не то что курсовой. Причины:

- FastAPI вместо Flask — правильный выбор в 2026 году (async, Swagger автоматом, Pydantic валидация)
- WebSocket для real-time обновлений — профессиональный подход
- SPA архитектура с роутингом — нетривиально для курсовой
- BME280 вместо DHT22 — датчик точнее + давление бонусом
- ZM106-VOC по UART — намного серьёзнее аналогового MQ-135
- SQLite с историей, экспорт CSV — полноценная база данных
- Demo режим с реалистичными данными — удобно для показа без железа

### Главная проблема

Весь JavaScript (1332 строки) — в одном файле `app.js`. Это:
- Сложно читать и отлаживать
- Нельзя нормально разделить задачи
- При поломке одной части — непонятно где искать
- Не по best practices современной веб-разработки

function calcWellnessIndex(s) {
  const scoreCo2  = s.co2  < 600  ? 100 : s.co2  < 800  ? 80 : s.co2  < 1000 ? 50 : 0;
  const scoreTemp = s.temperature >= 20 && s.temperature <= 25 ? 100 :
                    s.temperature >= 18 && s.temperature <= 27 ? 70 : 30;

@app.get('/api/wellness', tags=["Данные"])
async def get_wellness_index():
    s = get_latest()

    co2   = s.get('co2', 400)

    score_hum   = 100 if 40 <= hum <= 60 else 70 if 30 <= hum <= 70 else 30

    score_noise = 100 if noise < 40 else 80 if noise < 55 else 50 if noise < 70 else 0
    
    index = round((score_co2 + score_temp + score_hum + score_light + score_noise) / 5)
    level = 'excellent' if index > 80 else 'good' if index > 60 else 'fair' if index > 40 else 'poor'
    return {'index': index, 'level': level, 'components': {

### 5.3 Эндпоинт недельной статистики

```python
@app.get('/api/stats/week', tags=["Данные"])
async def get_week_stats():
    """Статистика по дням за последние 7 дней"""
    conn = get_db()
    rows = conn.execute('''
        SELECT
            DATE(timestamp) as day,
            AVG(co2) as avg_co2,
            AVG(temperature) as avg_temp,
            AVG(light) as avg_light,
            COUNT(*) as readings
        FROM sensor_data
        WHERE timestamp > datetime('now', '-7 days')
        GROUP BY DATE(timestamp)
        ORDER BY day ASC
    ''').fetchall()
    conn.close()
    return [dict(r) for r in rows]
```

### 5.5 Обнаружение аномалий (простое)

Если CO₂ вырос на >200 ppm за последние 10 минут — аномалия:

```python
def check_anomaly(current_co2: float) -> bool:
    conn = get_db()
    row = conn.execute('''
        SELECT co2 FROM sensor_data
        WHERE timestamp > datetime('now', '-10 minutes')
        ORDER BY id ASC LIMIT 1
    ''').fetchone()
    conn.close()
    if row and row['co2']:
        return (current_co2 - row['co2']) > 200
    return False
```

### 6.2 Что добавить — Frontend

#### TypeScript (вместо JavaScript)
**Что даёт:** Статическая типизация — IDE подсказывает ошибки ещё при написании кода.  
**Сложность:** Высокая — нужен компилятор (`tsc`) или сборщик.  
**Для курсовой:** Не нужно, излишне.  
**Для prod:** Однозначно да.

#### Vite (сборщик модулей)
**Что даёт:** Объединяет все JS/CSS файлы в один минифицированный бандл. Hot reload при разработке.  
**Сложность:** Средняя.  
**Для курсовой:** Опционально — только если делаем рефакторинг на модули.  
**Установка:** `npm create vite@latest`

#### PWA (Progressive Web App)
**Что даёт:** Сайт устанавливается на телефон как приложение. Работает оффлайн (кешируются последние данные).  
**Сложность:** Средняя — нужен Service Worker и manifest.json.  
**Для курсовой:** Интересная фича, несложная, впечатляет на защите.  
**Файлы:** `static/manifest.json` + `static/sw.js` (~50 строк суммарно)

```json
// manifest.json
{
  "name": "NEXIS Wellness Station",
  "short_name": "NEXIS",
  "start_url": "/",
  "display": "standalone",
  "theme_color": "#1a1a2e",
  "icons": [{ "src": "/static/icon-192.png", "sizes": "192x192" }]
}
```

### 6.3 Что добавить — Backend

#### Redis (кеш)
**Что даёт:** Хранит последние данные датчиков в памяти, не обращаясь к SQLite каждый раз.  
**Сложность:** Средняя — нужен отдельный процесс Redis.  
**Для курсовой:** Избыточно.  
**Для prod:** Да, при высокой нагрузке.

#### Alembic (миграции БД)
**Что даёт:** Система версионирования схемы базы данных. Изменение структуры таблиц через миграции.  
**Сложность:** Средняя.  
**Для курсовой:** Не нужно — SQLite создаётся с нуля при старте.

#### httpx (async HTTP клиент)
**Что даёт:** Нужен для Telegram Bot и любых внешних API запросов из FastAPI (async-совместимый).  
**Сложность:** Низкая, просто `pip install httpx`.  
**Для курсовой:** Да, нужен для Telegram уведомлений.

#### APScheduler (фоновые задачи)
**Что даёт:** Запуск фоновых задач по расписанию (например, ежедневный отчёт, очистка старых данных).  
**Сложность:** Низкая.

@scheduler.scheduled_job('cron', hour=18, minute=0)

**Что даёт:** Запуск сервера в контейнере — не нужно устанавливать Python и зависимости.  
**Сложность:** Средняя.  
**Для курсовой:** Не нужно, но выглядит профессионально.

### 6.4 Что добавить — Инфраструктура

#### MQTT (альтернатива HTTP POST)
**Что даёт:** ESP32 публикует данные в MQTT-брокер (Mosquitto), Python подписывается. Более эффективно чем HTTP для IoT.  
**Сложность:** Высокая — нужен отдельный Mosquitto брокер.

## 7. ESP32 АВТОНОМНЫЙ ВЕБ-СЕРВЕР

### Концепция

ESP32 может раздавать HTML/CSS/JS **сам**, без Python сервера. Телефон подключается к той же WiFi сети и открывает `http://192.168.1.XX` — видит дашборд напрямую с ESP32.

### Ограничения Flash памяти ESP32

| Что занимает | Размер | Влезает? |
|---|---|---|
| Прошивка (main.cpp скомпилированная) | ~800 KB | ✅ |
| index.html | ~50 KB | ✅ |
| style.css (минифицированный) | ~30 KB | ✅ |
| app.js (минифицированный) | ~80 KB | ✅ |
| Chart.js (полный) | ~200 KB | ✅ |
| Socket.io client | ~300 KB | ❌ Не влезет легко |
| Итого для файлов | ~660 KB | Осторожно |

Всего Flash: 4 MB. Под код ~1.5 MB. Под LittleFS: ~2 MB доступно.

### Облегчённая версия для ESP32

Если делать автономный режим — нужна упрощённая версия дашборда без тяжёлых библиотек:
- Вместо Chart.js — простые SVG-графики (~5 KB)
- Вместо Socket.io — нативный `EventSource` (Server-Sent Events) или polling
- Вместо SPA — обычные HTML страницы

### Рекомендация

```
Сейчас (для защиты):    Python сервер → богатый дашборд
После защиты (бонус):   ESP32 LittleFS → лёгкая версия без компа
```

Не стоит делать ESP32-версию вместо Python — потеряешь всю историю, графики и экспорт CSV.
